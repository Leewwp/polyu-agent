# 长期记忆在线回归

[返回回归总览](../README.md)

长期记忆业务回归的唯一推荐入口。走已启动服务的 Agent 对话接口 `/agent/v1/chat`，每个场景新建一个普通账号，数据库只读：不写消息、记忆和游标，不改提示词，不调 Judge。

机制（主动整理与后台学习的取数、来源与表达时间、提交与反馈）由 `agent` 模块的单元测试和 `AgentMemoryDatabaseTest` 用桩模型验证，这里只验真实对话里实际发生的业务行为。

## 场景

`--plan` 打印全部提问和计划对话次数，不调用模型。

| 场景 | 测什么 |
|---|---|
| S1 | 助手先问手机屏幕大小，用户答「我一直喜欢小的」并要求记住；新会话问偏好能否召回 |
| S2 | 先聊较重的头戴耳机，再说「一直戴不惯这么重的」：只能记成耳机偏好 |
| S3 | 小屏偏好可以记，「这次黑色就行」不能变成长期喜欢黑色 |
| S4A | 助手问是否戴眼镜，用户答「对，一直戴」：可以记 |
| S4B | 助手只是猜用户戴眼镜，用户回「好的谢谢」：不能记 |
| S5 | 给父亲买手机、父亲喜欢大屏：不记成用户的，也不新增父亲画像 |
| S6 | 「记住我下周出差，另外我一直戴眼镜」：只记眼镜，回答与工具清单一致 |
| S7 | 小屏 → 改大屏 → 新会话召回 → 撤回 → 新会话不再当有效记忆 |
| S8A | 手机/平板 A→B→A：对象各归各位，一批能覆盖两段会话 |
| S8B | 三句自然对话不要求记住：观察后台累计三条的路径，再新会话召回 |
| G1 | 本次黑色、给父亲买大屏混在选购对话里，再明确要求记住戴眼镜；新会话用上眼镜 |
| G2 | 记小屏 → 改大屏 → 记上海 → 撤回屏幕偏好 → 清空后只记杭州 → 新会话召回 |
| G3A | A 说喜欢大屏未整理，B 改口小屏并要求记住；A 后续三句触发后台，大屏不能被带回 |
| G4 | 两段会话三句自然对话不提记住：观察是否走后台累计三条 |

## 运行

服务与数据库先起好。管理员默认 admin/admin，可用 `RAGENT_ADMIN_USERNAME`、`RAGENT_ADMIN_PASSWORD` 覆盖，只用来建测试账号。

```bash
bash resources/regression/agent-long-term-memory/run.sh --plan                 # 看场景与计划次数，不调模型
bash resources/regression/agent-long-term-memory/run.sh --check                # 只做在线环境检查
bash resources/regression/agent-long-term-memory/run.sh --run --case S1        # 单场景，可写 S1,S2；S4 同时选中 S4A、S4B
bash resources/regression/agent-long-term-memory/run.sh --run                  # 完整套件，26 次对话
bash resources/regression/agent-long-term-memory/run.sh --run --repeat 2       # 每个场景换新账号重复
```

`--run` 先做环境检查，任何一项失败就不发对话请求：

- 服务进程启动时间不早于 `agent/target/classes` 里的记忆类；字节码里有记忆锁键、Judge 的 JSON 材料类型，以及主动整理、后台学习两个类
- 激活人设实际生效的抽取提示词（自己的或回落内置的）与仓库文件一致，且是 ADD/UPDATE/DELETE 决策加判定说明的输出协议
- 生效的工具说明要求按「本次实际发生的记忆变更如下」清单回报
- Redis 键 `ragent:agent:resolved-prompts:v2` 不存在或与库一致。**重启服务不会清掉这个键**，改了库里的提示词要删它

## 判定

每步程序自动判：回复是否完整、`flush_memory` 有没有调、主动整理是否提交成功、工具清单与库里实际新增/修改/删除/容量移除是否逐条对上（清空按逐条删除报），并记下后台游标前后位置和新条目来源（`FLUSH`/`BACKGROUND`）。主动整理不推进后台游标。

对象、归属、长期性和回答含义一律标「待复核」，由人读 `report.md` 里的原文判定，结论与理由写进同目录 `manual-review.md`。结果只有四种：通过、失败、未覆盖、待复核。

- 要求记住而主 Agent 没调工具：本步判定为「未覆盖」，不能说 Judge 判对了
- 助手没问出场景需要的问题：该场景前提不成立，按「未覆盖」记，不追加重试
- 「已经记住」看本轮工具结果和库里变化，不看回答结束后后台补写的结果
- 一次通过只说明这次通过，不代表准确率

退出码：`0` 无失败无待复核，`1` 有失败，`2` 仍有待复核（完整运行通常是 2）。

## 产物

`artifacts/<run-id>/`：`env.json`（环境检查）、`report.md`、`results.json`，每个场景一个子目录放 `step-*.sse` 原始响应与 `result.json`。测试账号默认保留，用户名与密码在 `artifacts/.credentials/<run-id>.json`，不进报告、不进 Git。

旧的七轮剧本、自然聊天和清理脚本已由本套件取代，历史运行产物仍在 `artifacts/` 下。
